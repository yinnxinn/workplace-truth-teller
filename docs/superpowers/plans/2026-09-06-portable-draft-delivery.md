# 通用草稿交付改进

用户已确定三层降级与跨运行平台配置目标，按现有授权直接实施。

维护源：当前配置 GitHub origin 的完整项目 `skill/`。其他本地副本只同步本次交付模块变更，保留独立内容生成改动。当前功能分支 `codex/portable-draft-delivery`。

## 范围

- 通用 JSON 配置：无账号凭据值、固定端口、浏览器 Profile 或操作系统依赖。
- Skill 指导宿主完成官方 API、授权浏览器、手动包三层交付。
- 离线计划器校验配置和能力快照，返回可执行下一步；不是独立 API 客户端或浏览器驱动。
- 模糊写入必须先回读；明确安全拒绝停止，不切换工具绕过。
- 公开发布不属于范围；真实凭据只从本机环境读取，不写入仓库或测试。后续在用户配置凭据与 IP 白名单后，增加官方 API 执行器并验证一次草稿创建与回读。

## 验证

运行 `python -m pytest skill/tests tests -q`；运行内置 `quick_validate.py skill`；运行 `git diff --check`。测试不连接公众号，不读取真实密钥。

回读成功必须具备草稿标识和账号、标题、正文、图片四项证据；计划器本身不能证明宿主快照真实，也不保证跨进程 exactly-once。

初次结果：主仓库 63 项离线测试通过；独立 Skill 副本 54 项通过（两者包含同一组 31 项交付决策测试，不累加为独立覆盖）。维护源与安装版的 Skill 校验通过，差异检查通过，安装版决策器与 JavaScript 语法检查通过。三处交付模块 SHA256 一致，相对文档引用全部存在；各自非交付模块的内容保留。

后续实测：新增 `wechat_api_delivery.py`，离线用例覆盖创建前回执、成功回读、超时不重试、重复执行防重、账号绑定内容身份、响应缺少草稿标识、回读不符与错误脱敏；主仓库总计 75 项、独立 Skill 副本 65 项测试通过。用户配置环境变量和 IP 白名单后，官方 API 成功上传封面、创建一篇草稿，并通过详情接口核对账号凭据引用、标题、正文和封面。没有调用发表接口。
